# MinIO 任务数据下载器（SDK 版 · Web 控制台 · Windows / Linux）

按“每个任务下载 N 条”的方式，把 MinIO 里的 episode 下载到多块本地磁盘，并提供 Web 控制台管理一切。

**这一版的特点**

- **使用官方 `minio` Python SDK，不依赖任何 `mc` 命令。**
- **下载是原子的**：正式文件名、正式目录里只会出现完整且已校验的数据（见[原子性](#原子性与数据完整性)）。
- **随时暂停、随时继续**：暂停会保存断点，继续时从断点接着下，不重复下载（见[暂停与继续](#暂停与继续)）。
- **所有配置都在 SQLite 里**：MinIO / PostgreSQL 连接、运行参数、任务、磁盘、访问口令，全部在 Web 页面上维护（见[配置](#配置都保存在-sqlite)）。
- **Windows 与 Linux / macOS 通用**，提供 `.bat` 与 `.sh` 启动脚本。
- 重新设计的 Web 界面：概览 / 任务 / 磁盘 / 连接 / 参数 / 日志，支持深色模式与手机宽度。
- **任务方案库 + 标签分类**：把一套任务存成方案，下次一键载入 / 追加，还能只取带某些标签的任务（见[任务方案与标签](#任务方案与标签)）。
- 加固过的 Web 层：防 CSRF / DNS 重绑定、口令错误限流、安全响应头（见[安全](#安全)）。

## 快速开始

### Windows

1. 安装 Python 3.10 或更新版本（<https://www.python.org/downloads/>，安装时勾选 **Add python.exe to PATH**）。
2. 双击 **`install.bat`**：创建虚拟环境并安装依赖（只需一次）。
3. 双击 **`run_web.bat`**：启动控制台并自动打开浏览器（默认 `http://127.0.0.1:8765/`）。
4. 在页面上依次完成（顶部会提示还缺什么）：
   - **连接**：填 MinIO 服务地址 / Access Key / Secret Key / Bucket，点“测试连接”；填 PostgreSQL 并测试；保存。
   - **磁盘**：添加目标磁盘，例如名称 `disk1`、路径 `D:\data`、挂载点 `D:\`；点“检查全部”确认；保存。
   - **任务**：确认场景与任务、各自的目标条数；保存。
5. 点右上角 **开始下载**。想停就点 **暂停**，之后点 **继续下载**。

### Linux / macOS

```bash
./install.sh          # 创建 .venv 并安装依赖（一次）
./run_web.sh          # 打开 http://127.0.0.1:8765/ ，在页面上完成配置后点“开始下载”
```

### 想让别的机器访问

默认只监听本机。要对外开放，先设口令，再改监听地址：

```bash
python web_app.py --set-token 你的口令       # 或在“参数”页设置
python web_app.py --host 0.0.0.0 --port 8765  # 或在“参数”页改监听地址，重启生效
```

没有设置口令时，控制台只接受本机直连（经过反向代理的请求也会被拒绝）；设了口令后，其它机器必须输入口令。
页面可以启动下载并删除本地数据，建议再放到内网或带 HTTPS 的反向代理之后。

## 安全

- **默认只监听本机**，且没设访问口令时只接受本机直连、`Host` 必须是 localhost / 127.0.0.1 / ::1（防 DNS 重绑定）；经过反向代理的请求会被拒绝。
- 写接口必须是 `application/json`，浏览器带 `Origin` 必须同源（防 CSRF）。
- 设了口令后，其它机器必须带口令；口令错误 8 次（5 分钟内）锁定 60 秒。口令只存 PBKDF2 哈希。
- 页面带 `X-Frame-Options: DENY`、CSP、`nosniff` 等响应头；API 不缓存。
- **口令是通过 HTTP 头传输的**：跨机器访问请放在带 HTTPS 的反向代理之后（nginx / Caddy 等），否则口令在局域网里是明文。
- Secret Key / PG 密码明文存放在配置库里，见下文“配置都保存在 SQLite”。
- 监控探活可用 `GET /healthz`（无需口令，只返回版本号）。
- 安装 `waitress`（`requirements.txt` 已包含）时使用它作为服务器；否则回退到 Flask 自带的开发服务器。

## Web 控制台

| 页面 | 作用 |
|---|---|
| **概览** | 总进度、已完成任务数、已下载时长 / 数据量；正在下载的每条数据的进度与**实时速度**；磁盘用量；按场景分组的任务进度（可折叠、筛选、只看未完成，点任务行展开未完成原因） |
| **任务** | 编辑版本目录、场景、任务、目标条数、历史别名、目录名、**标签**，调整顺序（即下载顺序）；顶部是**任务方案库**；可按标签筛选并批量改条数 |
| **磁盘** | 增删目标磁盘；“检查全部”会验证挂载点、写权限、剩余空间、是否与其它条目是同一文件系统 |
| **连接** | MinIO 与 PostgreSQL 连接；“测试连接”使用表单里尚未保存的值；Secret Key / 密码保存后不会再显示 |
| **参数** | 每盘并发数、保留空间、mcap 规则、重试、fsync、MD5 校验、监听地址 / 端口；访问口令；各文件位置 |
| **日志** | 实时跟随下载器日志，错误 / 警告高亮 |

顶栏的按钮在所有页面都可用：**开始 / 继续**、**暂停**、以及“⋯”菜单里的补齐轮数、重新检查缺文件、预览清理、清理缺 mcap 数据、强制结束。

> 配置修改在**下一次启动下载时**生效，当前正在跑的这一次不受影响。

## 任务方案与标签

**要解决的问题**：每一批下载的任务大同小异，不想每次重新录一遍；想把任务按类型分组，需要时只取其中一部分。

**标签**（分类）：在“任务”页表格的“标签”列给任务打标签，逗号分隔，如 `桌面, 分拣`。
标签条会列出所有标签和数量，点击即可筛选；筛选后可以**把这些任务的目标条数统一改成 N**。概览页也会显示标签，并能按标签搜索。
标签与“场景”不同：场景决定本地目录层级，标签只是分类，一个任务可以有多个，随时改，不影响磁盘上的路径，**下载器也不读取标签**。

**方案**（复用）：任务页顶部的“任务方案”卡片。

| 操作 | 说明 |
|---|---|
| 另存为方案 | 保存编辑器里**当前**的内容（含未保存的修改）；同名需换名，或对已有方案点“用当前覆盖” |
| 载入 → 替换 | 用方案替换当前任务配置，版本目录也取方案里的；已下载的数据不受影响 |
| 载入 → 追加 | 只添加当前没有的任务；已有任务（含条数）不变；与现有任务冲突（别名 / 目录名）的会被跳过，并告诉你原因 |
| 只载入某些标签 | 载入时勾选标签，只取带这些标签的任务（不选 = 全部） |
| 重命名 / 用当前覆盖 / 删除 | 只影响方案本身，不影响当前配置与已下载数据 |
| 导出 / 导入 | 导出为 JSON 文件，可拷到另一台机器导入；导入同名自动加序号，不会覆盖 |

典型用法：
1. 维护一个“全量任务库”方案，给每个任务打上标签（桌面 / 清洁 / 厨房…）。
2. 新一批只想下“桌面”类：载入这个方案 → 替换 → 勾选标签“桌面”，再用标签筛选把条数统一设为 20 → 保存任务 → 开始下载。
3. 下载中途想再补一类：载入方案 → **追加** → 勾选标签“清洁”，不会动已有任务。
4. 这批配置满意就“另存为方案”，下次直接载入。

方案保存在配置库里（`plans` 表，内容是任务的 JSON 快照）。首次启动会自动把初始任务存成方案“初始配置”。

## 暂停与继续

- **暂停**（页面按钮 / `stop_download.bat|sh` / `--stop` / 命令行里按一次 Ctrl+C）：下载器在**当前数据块写完后**停下，已写入的数据落盘，进度保存为 `paused`。通常几秒内完成。
- **继续**：再次“开始下载”。每个文件按 HTTP Range 从断点接着下；已完成的文件不会重新下载。
- **强制结束**（页面菜单 / 命令行里再按一次 Ctrl+C）：不等数据块写完。数据同样安全，只是最后一小段（最多约 64 MiB）需要重下。
- 进程被 `kill -9`、断电、断网时同理：正式目录里永远没有残缺数据，下次自动续传。

暂停不会产生“失败”记录，也不会清理暂存目录；如果你改了任务配置导致某条已暂停的数据不再被选中，下次启动时它的暂存目录才会被清理。

## 配置都保存在 SQLite

| 文件 | 内容 |
|---|---|
| `minio_downloader_config.sqlite3` | **配置库**：设置项、任务（场景 / 任务 / 别名 / 标签）、任务方案、磁盘、访问口令哈希 |
| `minio_download_state.sqlite3` | **状态库**：每条 episode 的下载状态、已下载记录、暂停请求、上次运行结果 |

两个文件分开：重置下载状态不会丢配置，反之亦然。位置默认与脚本同目录，可用环境变量
`MINIO_DOWNLOAD_CONFIG_DB` / `MINIO_DOWNLOAD_STATE_DB` / `MINIO_DOWNLOAD_LOG_DIR` 修改。

- **首次初始化**：配置库第一次创建时，自动导入已有部署的信息——代码里的默认任务列表、旧版 `tasks_config.json`、`minio_config.json`、`~/.mc/config.json` 里的 `minio1` alias（只读文件，不执行 mc）、`MINIO_*` / `MINIO_PG_*` 环境变量（见 `.env.example`）、`MINIO_WEB_TOKEN`。之后一律以配置库为准，改环境变量不再生效。Linux 下还会导入原来的三块默认磁盘；Windows 没有默认磁盘，需要在页面上添加。
- **PG 密码**：为保持升级后行为不变，首次导入且没设环境变量时沿用原脚本里的默认密码，请尽快在“连接”页改掉。
- **密钥安全**：Secret Key 与 PG 密码以**明文**存放在配置库里（POSIX 下文件权限 0600，Windows 请确保该目录只有你自己的账户可读）。它们不会通过 Web 接口返回给浏览器。访问口令只存 PBKDF2 哈希。备份配置库等同于备份密钥，请妥善保管。
- 想直接看内容：`sqlite3 minio_downloader_config.sqlite3 "select key,value from settings"`（密钥项会显示明文）。

## 命令行

```bash
./run_download.sh                                   # 按配置补齐各任务到目标条数（Windows：run_download.bat）
./run_download.sh --max-rounds 3                    # 缺文件被跳过时，最多改选后面的数据补 3 轮
./run_download.sh --recheck-missing                 # 重新检查以前记录为“缺文件”的数据
./run_download.sh --cleanup-missing-mcap --dry-run  # 只预览：哪些本地目录缺 mcap 将被删除
./run_download.sh --cleanup-missing-mcap            # 删除缺 mcap 的目录并重新补齐
./stop_download.sh                                  # 请求正在运行的下载器安全暂停
python minio_store.py check                         # 连接排查（读配置库）；另有 ls / get 子命令
```

同一时间只允许一个下载器实例（操作系统级文件锁，进程崩溃也会自动释放）；运行中的 PID 记录在 `minio_download.pid`。

## 原子性与数据完整性

目标：**任何时刻（包括进程被 kill、断网、磁盘写满、断电之后）读取方都不会看到写了一半的数据。**

```
MinIO ──list──▶ 清单（名字 / 大小 / ETag / 修改时间）
   │
   ├─ 每个对象 ─▶ .<名字>.<标记>.minio-tmp ──校验──▶ fsync ──os.replace──▶ 正式文件名      （文件级原子）
   │               ▲ 断线 / 暂停 / 重启后按 Range 续传
   │
   └─ 全部完成 ─▶ 核对清单（文件齐全、大小一致、无多余文件）─▶ fsync 目录
                  ─▶ rename  .<episode>.partial  →  <episode>                              （目录级原子）
                  ─▶ 写入 SQLite：completed
```

| 风险 | 对策 |
|---|---|
| 写到一半崩溃，留下残缺文件 | 数据只写临时文件；校验通过才 `os.replace` 成正式文件名 |
| 一条 episode 只下了一部分就“出现” | 整条先在 `.xxx.partial` 暂存目录里下载，校验通过后一次 `rename` 成正式目录 |
| 网络传输损坏 / 提前断开 | 字节数必须等于对象大小；ETag 是普通 MD5（无 `-`）时再校验内容；不符则丢弃重下 |
| 下载期间 MinIO 上的对象被替换 | 临时文件名带 ETag 标记，对象变了旧临时文件自动作废；下载完成后再 `stat` 一次，变了就拒绝 |
| 断电后临时文件尾部是脏数据 | 大文件每 32 MiB `fsync`；新进程续传时回退 64 MiB 再继续；ETag 可校验时全文件 MD5 兜底 |
| 暂存目录混入旧文件 | 完成前清理“不在本次清单内”的文件，最终目录与 MinIO 清单完全一致 |
| 对象名含 `..` / Windows 非法字符 | 拒绝写入并给出明确错误，不会越界写文件，也不会悄悄改名 |
| 改名成功但 SQLite 还没写 | 下次运行发现正式目录已存在，直接修复状态为 `completed` |
| 磁盘写满 | 识别 `ENOSPC` / `EDQUOT`，清理暂存目录，换下一块盘或标记 `waiting_space` |
| 网络故障被误判成“缺文件” | 列目录失败只记 `failed`（下次重试），**不会**记成 `missing_*`（默认会被一直跳过） |

**边界（请知晓）**

- ETag 带 `-` 的分片上传对象，ETag 不是内容 MD5，只能校验字节数（以及 TCP / TLS 的完整性）。有端到端校验和需求请在上传端另行处理。
- 开启了服务端加密（SSE）的对象，ETag 也可能不是 MD5；若反复出现“MD5 与 ETag 不一致”，在“参数”页关闭“校验 MD5”。
- 关闭“改名前 fsync”可以提速，但断电后不再保证数据已落盘（进程被 kill 仍然安全）。
- 暂存目录与正式目录在同一父目录（同一文件系统），所以 `rename` 是原子的。NFS / SMB / FUSE 等网络文件系统上的 `fsync` / `rename` 语义取决于实现，请自行评估。

## 状态与目录约定

本地目录：`<磁盘路径>/<版本目录>/<场景>/<目录名>/<episode>`；下载中是同级的 `.<episode>.partial`。

| status | 含义 | 下次运行 |
|---|---|---|
| `completed` | 已下载并原子发布 | 跳过（目录被删会重新下载） |
| `running` | 正在下载（下载器没在运行时表示上次被强制中断） | 续传 |
| `paused` | 已暂停，断点已保存 | 续传 |
| `failed` | 下载失败 / 暂时连不上 MinIO | 重试，可续传 |
| `waiting_space` | 所有目标盘暂时放不下 | 重试 |
| `retrying_space` | 写入时某块盘满了，换盘重试中 | — |
| `missing_task_info` / `missing_mcap` | MinIO 上缺必需文件 | 默认跳过，“重新检查缺文件”才重查 |
| `invalid_source` / `invalid_size` | `parent_key` 非法 / `file_size` 无效 | 需修数据 |

调度规则：每个任务固定在一块盘；每块盘同一时间只跑一个任务，任务内最多“每盘并发写入数”条同时下载；一条内最多“单条数据内并行文件数”个文件并行。

## Windows 注意事项

- **路径与挂载点**：数据目录例如 `D:\data`，挂载点填盘符根目录 `D:\`。下载器要求挂载点真实存在，防止盘没插好时写进系统盘。
- **路径长度**：默认路径上限约 260 字符。数据目录层级较深时，请启用长路径（组策略 / 注册表 `LongPathsEnabled=1`），并让磁盘路径尽量短（如 `D:\d`）。
- **对象名**：MinIO 上含 `: ? * " < > |`、以空格或点结尾、或叫 `CON` / `NUL` / `COM1` 等的文件名无法在 Windows 落盘，会得到明确错误；本地的场景 / 任务目录名遇到保留名会自动加 `_` 前缀。
- **杀毒软件 / 索引服务**：可能短暂占用刚写完的文件，导致改名失败；程序会自动重试几次。建议把数据目录加入杀毒软件的排除项。
- **后台运行**：关闭浏览器不影响下载。下载进程以独立进程组、无控制台窗口的方式启动，设计上关闭 `run_web.bat` 的窗口不会结束它（状态靠 PID 文件识别）；这一点同样需要在 Windows 上实测确认。要开机自启，可用“任务计划程序”运行 `run_web.bat`，或用 NSSM 把 `.venv\Scripts\python.exe web_app.py` 注册为服务。
- **本版本未在真实 Windows 上实测**（开发环境是 Linux）。Windows 相关代码（文件锁、进程管理、路径检查、改名重试）已按平台分支实现，并用模拟方式测试了其逻辑；首次使用请先用一个目标条数为 1 的小任务验证，遇到问题欢迎反馈。

## 排查

| 现象 | 处理 |
|---|---|
| 页面顶部提示“开始之前还需要…” | 按提示到对应页面补全；“开始下载”在补全前是灰的 |
| 测试连接：`AccessDenied` / `SignatureDoesNotMatch` | 检查 Access Key / Secret Key、bucket 权限、服务器时间偏差 |
| 测试连接：SSL / 证书错误 | 核对服务地址的 `http://` / `https://`；内网自签证书可关闭“校验证书” |
| `MD5 与 ETag 不一致` 反复出现 | 对象可能启用了 SSE，关闭“校验 MD5” |
| 任务一直 `waiting_space` | 该任务整体放不进它固定的那块盘（含安全系数和保留空间）；腾空间或调小“保留空间” |
| 磁盘页提示“挂载点没有真正挂载” | 挂载点必须是真实的挂载点 / 盘符根目录；路径要在它之下 |
| 点暂停后很久没停 | 正在等待一次很慢的网络读取（读取超时默认 120 秒）；可用菜单里的“强制结束”，数据仍安全 |
| 概览显示“已中断” | 上次下载器被强制结束 / 崩溃，这些条目下次会续传 |
| 单条数据详情 | `logs/episode_<id>.log`；总日志 `logs/minio_task_downloader.log` |
| 忘记访问口令 | 在本机运行 `python web_app.py --set-token 新口令` |

## 部署（systemd 示例）

```ini
# /etc/systemd/system/minio-downloader-web.service
[Unit]
Description=MinIO downloader web console
After=network-online.target

[Service]
User=downloader
WorkingDirectory=/opt/minio_downloader
ExecStart=/opt/minio_downloader/.venv/bin/python web_app.py
# 默认 systemd 停止服务时会杀掉 cgroup 内所有进程（含下载进程）。想让重启 Web 不打断下载，加上：
KillMode=process
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## 已知问题

- 任务级空间预检是“整体放得下才开始”，放不下则整个任务本轮跳过（沿用自原脚本，未改动）。
- 任务元数据来自 PostgreSQL 表 `public.minio_galbot_scene_task_jobs` / `minio_galbot_scene_task`，表名写在脚本里。
- 真实 MinIO、真实 Windows 的行为没有自动化验证（见上文各处说明）。
